Dijkstra 最短路徑

Dijkstra's Algorithm

每次確定一個離起點最近的節點，求非負權重圖的最短路徑。

01直覺

從政大騎車去好幾個地方，每條路要花的時間不同。Dijkstra 的想法是：在所有「還沒確定」的地點中，目前估計最近的那一個，它的距離一定已經是最短了，因為任何繞路都只會更遠（前提是沒有負的路段）。

確定它之後，再用它去更新鄰居的估計值，這個動作叫鬆弛（relaxation）。用優先佇列（priority queue）就能每次快速拿出「目前最近」的節點。

每次確定最近的那一個，再用它去縮短鄰居的距離。

02步驟

  1. 起點距離設為 0，其餘設為無限大；把 (0, 起點) 放進優先佇列。
  2. 從優先佇列取出距離最小的 (d, u)。
  3. 若 d 大於目前記錄的 dist[u]，代表是過期紀錄，略過。
  4. 對 u 的每條邊 (v, w)：若 d + w < dist[v]，更新 dist[v] 並把新距離放進佇列。
  5. 重複第 2–4 步，直到佇列清空。

無向圖的邊為 A–B(4)、A–C(1)、C–B(2)、B–D(1)、C–D(5)、D–E(3)，從 A 出發。表格中是每一步結束後的距離表，∞ 表示還沒到過。

最短距離：A=0、B=3、C=1、D=4、E=7。A 到 E 的最短路徑是 A → C → B → D → E。

04複雜度

時間（二元堆積）
O((V + E) log V)

每條邊最多觸發一次 push，每次 push／pop 為 O(log V)。

時間（陣列找最小）
O(V²)

每回合掃一遍陣列找最小值；適合邊非常密的圖。

空間
O(V + E)

距離表 O(V)，佇列中可能累積 O(E) 筆過期紀錄。

05Python 實作

import heapq


def dijkstra(graph: dict[str, list[tuple[str, int]]], start: str) -> dict[str, float]:
    """回傳 start 到每個節點的最短距離（邊權重必須非負）。"""
    dist = {u: float("inf") for u in graph}
    dist[start] = 0
    heap = [(0, start)]                 # (目前距離, 節點)
    while heap:
        d, u = heapq.heappop(heap)
        if d > dist[u]:                 # 過期的舊紀錄，略過
            continue
        for v, w in graph[u]:
            if d + w < dist[v]:         # 鬆弛：找到更短的路
                dist[v] = d + w
                heapq.heappush(heap, (dist[v], v))
    return dist


if __name__ == "__main__":
    g = {
        "A": [("B", 4), ("C", 1)],
        "B": [("A", 4), ("C", 2), ("D", 1)],
        "C": [("A", 1), ("B", 2), ("D", 5)],
        "D": [("B", 1), ("C", 5), ("E", 3)],
        "E": [("D", 3)],
    }
    print(dijkstra(g, "A"))
    # {'A': 0, 'B': 3, 'C': 1, 'D': 4, 'E': 7}

06常見陷阱

圖中有負權重　「目前最近的就已確定」這個前提會失效，答案可能錯。有負邊時改用 Bellman-Ford。

放進佇列時就標記為完成　節點要在被取出時才算確定，不是被放進去時。這點和 BFS 剛好相反，很容易寫混。

沒有略過過期紀錄　Python 的 heapq 不能修改既有元素，同一節點會留下多筆舊距離。少了 if d > dist[u]: continue 雖然結果仍對，但會做大量白工。

07相關演算法

  • 廣度優先搜尋　所有邊權重都是 1 時，Dijkstra 會退化成 BFS，而 BFS 用普通佇列就夠了。
